2   Recommended architecture

Replace Attributes and ConsoleAttributes with small injectable facets:
FACET	                    RESPONSIBILITY
RuntimeConfiguration	    Environment, absolute project paths, resolved XML configuration, and DisplayErrors policy
LoggerService	            Wraps the selected Lucinda\Logging\Logger
HeadersService	            Wraps Lucinda\Headers\Wrapper
SqlService / NoSqlService	Wrap the final engine providers
TranslationService	        Wraps Internationalization\Reader
SecurityContext	            Current packet, user ID, CSRF token, bearer token, and relevant OAuth2 state

Listeners should receive existing facets through constructor injection and return one new facet where appropriate.
Use separate listeners rather than MultiFaceted until the FacetCollection iteration bug is fixed.

A scheduler factory should define lifecycle ordering centrally:
    START
    Runtime configuration

    APPLICATION
    SQL provider
    NoSQL provider

    REQUEST
    STDERR format synchronization
    Logging
    Headers
    CORS/preflight
    Localization
    Security

    RESPONSE
    Cache/status/header transformation

    END
    Process-wide registry cleanup, if used

ServiceRegistry should be retained only where a dependency constructs project classes without injection—particularly
security DAOs and custom PHP session handlers. Normal controllers, listeners, and resolvers should use facets.

1. Stabilize Composer and bootstrap
- Remove the obsolete autoload.files entries.
- Regenerate Composer autoload metadata.
- Decide whether Configurer is being upgraded, replaced, or temporarily removed.
- Resolve or document the dependency issues above.
- Rewrite index.php around:
  - Lucinda\MVC\EventScheduler
  - Lucinda\MVC\EventType
  - new STDOUT/console constructors
  - new STDERR collaborators
  - PHP_SAPI === "cli" instead of $argv detection
Exit criterion: requiring vendor/autoload.php works, and minimal HTTP and CLI front controllers can start.

2. Rebuild configuration
Split the MVC configuration into manifests and referenced files, for example:
config/
  stdout.xml
  stdout/
    application.xml
    resolvers.xml
    routes.xml
    session.xml
    cookies.xml
  stderr.xml
  stderr/
    application.xml
    resolvers.xml
    routes.xml
  services/
    templating.xml
    logging.xml
    headers.xml
    sql.xml
    nosql.xml
    internationalization.xml
    security.xml
    oauth2.xml
The application definitions must now include views_folder and views_extension. RuntimeConfiguration should load
service configuration and resolve paths relative to the project root, avoiding dependence on the process working
directory.

3. Restore the smallest vertical slice
Implement only:
- HTML resolver
- JSON resolver
- console resolver
- default index route
- STDERR display policy
- error controller
- fatal fallback resolver
- error reporter
Resolvers now implement Lucinda\MVC\Response\ViewResolver and return strings. Controllers implement ViewAware or ViewUnaware and receive dependencies in constructors.
The custom TemplatingWrapper and ViewCompilationException should be retired: the new View Language wrapper already converts rendering failures into source-aware ViewExceptions.
Use separate success and error JSON resolvers, or define a single explicit envelope convention. The old debug_backtrace() test for determining whether JSON came from STDERR should not be carried forward.
Exit criterion: index HTML/JSON/console rendering works, and a thrown exception produces the configured safe or debug response.

4. Restore infrastructure integrations
Port SQL, NoSQL, logging, and localization next.
- Use Framework Engine’s lazy SQL/NoSQL providers.
- Retain SQL() and NoSQL() temporarily as compatibility façades if desired, but implement them over the new providers.
- Replace the project Loggers\File and Loggers\SysLog with Logging API’s built-in wrappers.
- Update translate() to use the new Reader interpolation API, or prefer injecting TranslationService.
- Keep database-dependent tests out of the default unit suite.
The existing session and migration cache classes are mostly portable, but should be hardened around the new driver behavior and tested separately.

5. Restore HTTP headers and caching
- Build the headers wrapper during the request lifecycle.
- Handle OPTIONS with TerminationException plus Blank, ByStatus, or Redirect; do not call exit() from a listener.
- Implement caching as a response transformer combining Body, Status, and Headers.
- Compute body-based ETags from the string passed to transform(). The new generic Response interface no longer exposes getBody(), so the old cacheables cannot preserve their behavior unchanged.
- Add coverage for 200, 304, and 412, CORS headers, credentials, and Vary: Origin.

6. Reimplement security as a separate milestone
Security contains the largest semantic change and should not block the basic skeleton.
- Use RequestBinder and OAuth2\ServiceBinder.
- Add an OAuth2State implementation.
- Build a RolesDetector when route-based authorization is configured.
- Treat returned packets as expected workflow outcomes, not exceptions.
- Translate packets into either:
  - a SecurityContext facet when request processing may continue, or
  - an immediate redirect/status response when the packet requires action.
Delete the old Controllers\SecurityPacket: SecurityPacket exceptions no longer exist.

Rewrite the SQL/NoSQL throttlers against the new DAO\Throttler\FormLogin contract in [FormLogin.php (line 13)](Z:/home/aherne/framework/framework-skeleton/vendor/lucinda/security/src/DAO/Throttler/FormLogin.php:13). Preserve the old exponential penalty behavior explicitly if it remains desired. Also correct the old NoSQL persistence call, which accidentally supplied the expiration value to json_encode() rather than Driver::set().
The removed OAuth2 DriverDetector behavior needs to be re-specified: provider resource access for an authenticated user is no longer directly represented by the new framework engine.

7. Finish persistence, tooling, tests, and documentation
- Modernize migrations.php to use the same runtime configuration and providers.
- Decide the future of configure.php.
- Rewrite the 47 existing test files by behavior; they cannot be incrementally repaired because most construct removed base classes.
- Use fakes for SQL, NoSQL, logging, OAuth2, and security unit tests; keep live MySQL/Redis tests opt-in.
- Add front-controller smoke tests for HTTP, console, STDERR, and early termination.
- Run PHPStan after each slice.
- Finally align the project version: the branch, Composer description, README, and welcome template currently advertise different generations.
Class disposition
- Remove: Attributes, ConsoleAttributes, TemplatingWrapper, ViewCompilationException, custom logger wrappers, and Controllers\SecurityPacket.
- Rewrite: all event listeners, view resolvers, error handling classes, security integration, and login throttlers.
- Adapt: cacheables, session handlers, migration caches, and helper functions.
- Preserve only as behavioral references: src_old, current tests, and old XML fixtures.
The best first implementation milestone is phases 1–3: a clean autoload, valid split configuration, new bootstrap, basic resolvers, and a working STDERR pipeline. That establishes the architecture before database, headers, and security complexity is reintroduced.
